Extracting Financial PDF Tables to Excel (.xlsx) 100% Locally in Your Browser

How PDFGod converts multi-page bank statements, EOBs, and invoices into native Microsoft Excel workbooks with borders, numeric formatting, and edits preserved—with zero cloud uploads.

1. The Challenge: PDFs Have No Concept of "Tables" or "Cells"

Unlike HTML or Excel spreadsheets, the PDF format has no <table>, <tr>, or <td> tags. Under the hood, a financial table in a PDF is simply a flat collection of unrelated drawing commands: horizontal strokes, vertical divider lines, rectangles, and positioned text strings scattered at arbitrary floating-point coordinates.

Basic copy-and-paste flattens every row into broken single-column text, while online PDF-to-Excel converters force you to upload confidential payroll sheets, medical EOBs, and tax schedules to unknown third-party servers.

2. How PDFGod Reconstructs Excel Workbooks (Inside js/excel-exporter.js)

Step 1: Extracting Text Baselines & Operator-List Vector Borders

On every page, PDFGod reads both page.getTextContent() and the low-level graphics operator list (page.getOperatorList()). By walking vector path commands (moveTo, lineTo, rectangle, stroke), PDFGod detects horizontal table rules, vertical column separators, and filled header shading rectangles.

Step 2: Respecting In-Editor Redactions, Edits & Annotations

Because the Excel exporter sits inside the PDFGod editor rather than running blindly on the raw file:

  • Any original PDF text deleted or covered by whiteout/blackout redactions is excluded automatically from Excel output.
  • Any edited text fields or newly typed annotations (including Thai Sarabun labels) are merged directly into their corresponding spatial coordinates in the exported worksheet.

Step 3: Spatial Row & Column Clustering + Native Number Detection

PDFGod clusters text spans that share vertical Y-baseline tolerance into logical spreadsheet rows, aligns column boundaries against both vector grid dividers and X-projection gaps, and parses numeric currency values (`$1,234.50` → clean numeric cell values rather than dead strings) so `SUM()` and Excel formulas work immediately upon opening.

Step 4: Zero-Dependency OpenXML (.xlsx) ZIP Generation

To keep PDFGod portable inside a single offline file with zero external NPM runtime dependencies, ExcelExporter generates all required OpenXML parts in memory—[Content_Types].xml, xl/workbook.xml, xl/styles.xml (with bold headers and cell borders), and per-page xl/worksheets/sheetN.xml—and archives them with a built-in CRC32/Store ZIP packager before writing to disk via showSaveFilePicker.
