About PDFGod & Client-Side Security Architecture

Why PDFGod was built as a zero-upload, self-contained browser application—and how its internal rendering and vector reconstruction engines work.

1. Project Mission: Why 100% Client-Side Matters

Every day, millions of users need to make quick, critical edits to PDF documents—correcting a typo on an invoice, signing a lease agreement, redacting an account number on an Explanation of Benefits (EOB), or converting a financial table into Excel.

Most online PDF tools require uploading your file to a remote cloud server for processing. For confidential legal, medical, tax, and corporate documents, uploading files to third-party servers introduces unacceptable privacy and compliance risks. Furthermore, heavy desktop software suites often require expensive subscriptions and gigabytes of disk space.

PDFGod bridges this gap by bringing a complete, desktop-grade PDF editing and vector export suite directly into the browser's local memory—compiled into a single, portable HTML file that requires zero server uploads, zero accounts, and works offline.

2. How the Client-Side Engine Works

A. Dual-Engine Rendering & Vector Reconstruction

PDFGod pairs two complementary open-source engines inside an isolated browser sandbox:

  • Mozilla PDF.js (v3.11) + Inline Web Worker: Parses incoming PDF byte streams, extracts exact glyph bounding boxes, font matrices, and vector stroke coordinates, and renders crisp high-DPI canvas viewports.
  • PDF-Lib (v1.17) + Fontkit TrueType Shaper: When saving or exporting, PDFGod does not rasterize pages into blurry images. Instead, it modifies the native PDF object graph directly—embedding TrueType font subsets, writing vector paths, and serializing a standard-compliant PDF binary.

B. Spatial Grid & OpenXML Excel (.xlsx) Reconstruction

The built-in Excel exporter (`ExcelExporter`) inspects horizontal and vertical vector path operators (`m`, `l`, `re`) alongside text baseline coordinates on each page. Using spatial clustering, it reconstructs rows, columns, merged cells, and border weights, packaging them into a valid OpenXML `.xlsx` ZIP archive directly in JavaScript memory.

C. W3C File System Access API Integration

On modern Chromium browsers, PDFGod leverages `window.showOpenFilePicker`, `window.showSaveFilePicker`, and `FileSystemFileHandle.createWritable()` to allow direct in-place saving over your existing local file—delivering the exact save workflow of a native desktop application.
